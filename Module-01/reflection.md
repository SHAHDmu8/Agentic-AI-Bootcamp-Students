# Module 1 — Agent Loop Reflection

During offline testing, I simulated a case where the agent repeated the same `lookup` action for France twice in a row. The loop detection guard correctly identified the repeated action and stopped execution instead of allowing the agent to continue unnecessarily. I also tested a malformed JSON response, and the retry mechanism successfully recovered when the next response contained valid JSON. Adding the `lookup` tool alongside the `calculator` made the agent more capable, but it also introduced an additional routing decision that could go wrong. For example, a question asking for both the capital of France and the result of 12 × 12 requires the agent to select two different tools across separate steps before producing its final answer. The offline multi-tool test confirmed that the agent could complete this sequence using mocked model responses. These tests helped me understand why tool routing, output validation, and loop detection are important for building reliable AI agents.
